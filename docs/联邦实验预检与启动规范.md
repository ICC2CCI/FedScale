# 联邦实验预检与启动规范

本规范适用于本仓库的 Flower 跨中心联邦微调实验。目标是在提交前发现缓存、模板和
客户端状态问题，避免出现 Run 秒级失败或 GPU 未创建训练 Job 的情况。

## 必须满足的启动条件

1. 中心端 `superexec-serverapp`、客户端 A/B 的 `superexec-clientapp-*` 均为 Ready。
2. **同一基座模型必须完整缓存于中心端、A、B 三处**。
   ServerApp 负责加载初始参数；仅 A/B 缓存模型时，Run 会在创建训练 Job 之前失败。
3. 模板与模型类型匹配：
   - `Qwen/*`：将 Alpaca 的 `instruction + input` 映射为 `user`，`output` 映射为
     `assistant`，用 tokenizer 的 `apply_chat_template` 生成 ChatML。
   - `openlm-research/open_llama_3b_v2`：该基座没有 chat template，使用 Alpaca
     completion 格式，并仅对 `### Response:` 后的 token 计算 loss。
4. 数据集在 A/B 的离线缓存中可用；训练环境启用了 `HF_DATASETS_OFFLINE=1`。
5. 新实验与对照实验应保持模型、数据集、轮数、LoRA 参数、评测样本和评测参数一致，
   仅改变待比较变量（例如 `fsdp` 与 `ddp`）。

## 标准启动方式

```bash
# 终端 1：保持 Flower 控制连接
./scripts/port-forward.sh

# 终端 2：run-federated.sh 会自动执行预检，失败则不会提交。
./scripts/run-federated.sh \
  --model openlm-research/open_llama_3b_v2 \
  --strategy fsdp \
  --dataset vicgalle/alpaca-gpt4 \
  --rounds 50
```

可单独执行预检：

```bash
./scripts/preflight.sh openlm-research/open_llama_3b_v2
```

`--skip-preflight` 仅限明确诊断目的；不得用于常规提交。

## FSDP 与 DDP 对照

正式的 FSDP/DDP 参数、实验 ID、实测结论与复现命令见
[`fsdp_vs_ddp.md`](fsdp_vs_ddp.md)。原始结果保存在集群结果卷，按需导出到本机
`evaluation-results/`；该目录属于运行产物，不提交到 Git。

FSDP 实验完成后，使用完全相同的 held-out 样本、teacher-forcing loss、生成参数和
指标（Loss/PPL、ROUGE-L、BERTScore、空回答数、生成长度）重新评测。不要将训练日志
中的局部 loss 与该评测报告的 held-out 指标直接比较。

## 异常处理顺序

1. `status.sh`：确认是否创建了两端 `train-round-*` Job。
2. 若 Run 秒级结束，先执行 `flwr log RUN_ID cross-cloud`，优先检查中心端模型缓存。
3. 若 Run 已停止但 Job 仍运行，先删除**明确命名**的临时 Job，再重启 A/B ClientApp，
   以免客户端对不存在的 Job 持续 404 轮询。
4. 不删除模型缓存、结果 PVC 或历史 checkpoint。
