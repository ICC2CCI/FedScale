# 联邦实验运行与运维指南

仓库根目录是当前跨中心 Flower 联邦微调实验的运维入口。训练由中心端 ServerApp
执行 FedAvg 聚合，两个 ClientApp 分别在 A/B 集群创建三节点、三 GPU 的 DDP 或
FSDP 训练 Job。

所有命令从仓库根目录执行：

```bash
cd /path/to/flower-llm
```

## 正确启动方式

终端 1：建立并保持 Flower CLI 控制连接。

```bash
./scripts/port-forward.sh
```

终端 2：提交实验。下面这条命令有效；`experiment-id` 已在 Flower 应用配置中
登记，用于中心端持久结果目录。

```bash
./scripts/run-federated.sh \
  --model openlm-research/open_llama_3b_v2 \
  --strategy fsdp \
  --dataset vicgalle/alpaca-gpt4 \
  --rounds 5 \
  --experiment-id openllama-fsdp-5
```

普通提交默认执行预检：检查中心端、A/B 的 Deployment 就绪状态及**模型快照**。
若缺少模型快照，会自动预热对应端并复检。预检不验证数据集是否已缓存；训练
Pod 使用离线数据集模式，数据集缺失会在训练启动时失败。

自动恢复实验使用：

```bash
./scripts/run-resilient-federated.sh \
  --model openlm-research/open_llama_3b_v2 \
  --strategy fsdp \
  --dataset vicgalle/alpaca-gpt4 \
  --rounds 50 \
  --experiment-id openllama-fsdp-50-resilient
```

该脚本每个成功聚合轮次保存一次全局 LoRA checkpoint；遇到可判定失败时，最多
自动恢复 3 次，并仅从最后一个成功 checkpoint 继续。

### 快速联邦冒烟实验

要缩短单轮时间，优先保持当前已缓存、字段已适配的 `vicgalle/alpaca-gpt4`，并减少
每客户端样本数和本地优化步数。例如每端最多 3,000 条样本、每轮最多 10 个优化步：

```bash
./scripts/run-resilient-federated.sh \
  --model openlm-research/open_llama_3b_v2 \
  --strategy fsdp \
  --dataset vicgalle/alpaca-gpt4 \
  --rounds 2 \
  --experiment-id openllama-fsdp-smoke \
  --max-restarts 3 \
  --poll-seconds 60 \
  --stall-seconds 7200 \
  --set dataset.max-train-samples=3000 \
  --set train.training-arguments.max-steps=10 \
  --set train.evaluate-after-fit=false
```

训练实验默认关闭阻塞联邦轮次的本地模型评估；训练完成后再用独立评估任务测试全局
checkpoint。2026-07-27 的历史冒烟实验曾在每轮额外评估 5 条样本，其端到端 Flower
Run 耗时为 52 分 15 秒，但两轮纯 GPU 训练关键路径合计约 33 分 1 秒，二者不能混称。
若确需诊断轮内评估，可显式设置 `train.evaluate-after-fit=true` 和
`train.num-eval-samples=5`；此时报告仍会分别记录训练、评估和端到端耗时。

可以使用其他 LoRA 指令数据集，但需先在 A/B 缓存数据，并确保数据被规范化为
`instruction`、可选 `input`、`output` 字段；当前加载器不会自动识别任意数据集的
字段名。快速实验不应与完整数据集的 FSDP/DDP 正式指标直接比较。

### 训练与评估口径

- 本地优化步：一个客户端在一次联邦轮次内执行一次 `optimizer.step()`。当前每张卡
  batch size 为 4，梯度累积 12 次，3 个 FSDP rank 合起来的理论有效 batch 为
  `4 × 12 × 3 = 144` 条样本呈现；`max-steps=10` 表示最多更新 10 次，不是只读取
  10 条数据，也不是 3 张卡各自形成 30 次独立模型更新。
- 评估样本：从客户端训练分区再划出的 held-out 数据，只做前向计算、验证 loss/PPL
  或生成指标，不反向传播，也不参与 FedAvg 权重更新。
- `max-steps` 为正数时优先于 `num-train-epochs`。本次每客户端 3000 条先按 90%/10%
  切成 2700 条训练、300 条验证；3 个 rank 各分到约 900 条训练数据。10 个优化步
  理论呈现约 `10 × 144 = 1440` 条样本，只覆盖约 0.53 个 epoch，因此不会完成
  配置中的 3 个 epoch。
- Train loss 是各客户端训练时、用于反向传播的 assistant-response-only 交叉熵；
  报告中的客户端训练 loss 是这些标量按客户端训练集大小做的加权均值，不是聚合后
  全局模型的 loss。Validation loss 则是在 held-out 数据上、参数冻结且无梯度时计算的
  response-only 交叉熵，用于观察泛化，两者数据和模型时点不同，不能当成同一个量。
- 报告同时保留纯训练、轮内评估、客户端轮次和实验端到端墙钟时间。系统吞吐比较看
  纯训练时间；部署与调度 SLA 看端到端时间。

### 客户端采样比例

Flower 命令：

```bash
flwr run . \
  --run-config "num-server-rounds=50 strategy.fraction-train=0.25" \
  --stream
```

表示执行 50 个全局聚合轮，并在每轮从当前可用客户端中抽取 25% 参加训练。
实际数量还受 `strategy.min-fit-clients` 下限约束。当前只有 A/B 两个客户端，且
`min-fit-clients=2`，所以即使比例为 0.25，每轮仍会抽取两个客户端；只有扩展到更多
SuperNode 后，该比例才会减少每轮参与数量。`--stream` 只表示在当前终端持续输出 Run
日志，不改变训练算法。

### NVLink 与当前 TKE 拓扑

当前 A/B 都是三台 `GN10X.2XLARGE40`，每台只有一张 V100 32GB；三张卡之间经过
跨节点网络，不存在可由 Kubernetes YAML 打开的 NVLink。NVLink 是物理机内 GPU
互联，必须把节点池改为同一实例内含 2/4/8 张 GPU 的规格，再将同一客户端的多个
rank 调度到该多卡节点。`DIST_GPUS_PER_NODE>1` 时启动器使用 `torchrun` 为每张卡创建
一个本地 rank；部署后应通过 `nvidia-smi topo -m` 验证卡间链路，而不是仅看实例名称。

### 全参数 FP16 的 FSDP/DDP 内存对照

`run-federated.sh` 支持 `--finetuning-type full --quantization 0`。训练使用 FP32
主参数和优化器状态、V100 上的 FP16 AMP 前后向计算；Flower 通信边界统一把完整
state 转为 FP16，聚合 checkpoint 保存为中心端 `full_N/model_state.pt`；
LoRA 仍保存为 `peft_N/adapter_model.bin`。DDP 的实验性 CPU AdamW 状态卸载通过
`--ddp-cpu-offload` 开启，只能与 DDP 一起使用。全模型每客户端每轮传输约 6.5GB，
所以报告必须分别比较纯训练时间和端到端联邦通信时间。

首次全参数实验可使用 `--full-local-init` 跳过初始 6.5GB 下发，但只允许从第 1 轮
新实验启动。预检会要求中心、A、B 的 Hugging Face snapshot ID 完全一致；后续客户端
更新仍会正常回传并执行 FedAvg。训练 Job 禁用 Hugging Face Trainer 自带 checkpoint，
避免 3 个 rank 在共享 PVC 的同一目录竞争写文件；联邦 checkpoint 仍由 rank 0 和
中心端按轮保存。

## 结果、权重与日志

| 类型 | 位置 | 可否作为全局模型 |
| --- | --- | --- |
| 全局 FedAvg checkpoint | 中心端 LoRA：`peft_N/`；全参数：`full_N/model_state.pt` | 可以。必须与对应模型、微调方式和配置一起加载。 |
| 实验状态与联邦指标 | 中心端 `/app/results/<experiment-id>/experiment_state.json`、`federated_metrics_round_N.json` | 用于判断运行状态、成功轮次及恢复点。 |
| 客户端训练输入 | A/B `/app/outputs/train-round-<N>-<partition>-<timestamp>/initial_weights.pt` | 这是本轮下发的全局输入；若 A/B 同一轮哈希相同，可用于证明此前一轮的聚合结果。 |
| 客户端本地更新 | A/B 同目录 `model_weights.pt` | 不可以。它是本地训练完成后的更新，不能冒充 FedAvg 聚合模型。 |
| 评测输出 | A/B `/app/outputs/evaluations/<name>/summary.json` | 取决于使用的 adapter；本地模型评测必须标为 `client-local`。 |
| 持久日志 | 中心端 `/app/persistent-logs/`；A/B `/app/persistent-logs/` | 保留容器输出、终止信号与重启前原因。 |

中心端的模型缓存 `/app/.cache` 使用 `superexec-serverapp-cache-pvc`（50Gi CBS
PVC），A/B 使用各自 `flowertune-cache-pvc`。模型预热成功后，Pod 重启不会再清空
缓存；镜像仓库不是缓存持久化的前置条件。

查看中心端全局结果：

```bash
./scripts/list-results.sh
```

## 常用操作

| 命令 | 用途 |
| --- | --- |
| `./scripts/preflight.sh MODEL` | 检查三端服务与模型快照；默认自动预热缺失模型。加 `--no-warm` 可只检查。 |
| `./scripts/warm-model-cache.sh MODEL [--target center\|a\|b\|all]` | 单独预热指定端的模型缓存。 |
| `./scripts/run-federated.sh ...` | 提交可配置实验，支持模型、FSDP/DDP、数据集、轮数、恢复参数与实验 ID。 |
| `./scripts/run-resilient-federated.sh ...` | 提交带 checkpoint 自动恢复的实验。 |
| `./scripts/status.sh` | 查看三端 Deployment、Pod、训练 Job。 |
| `./scripts/logs.sh {server\|a\|b\|all} [--follow]` | 查看三端容器日志。 |
| `./scripts/list-runs.sh` | 列出 Flower Run。 |
| `./scripts/list-results.sh` | 汇总中心实验状态、策略、模型、耗时、checkpoint 和指标数量。 |
| `./scripts/export-experiment-report.sh ID [DIR]` | 将中心 PVC 元数据导出为本地中文实验报告，不复制 LoRA 权重。 |
| `./scripts/stop-run.sh RUN_ID` | 停止明确指定的 Flower Run。 |
| `./scripts/delete-training-job.sh {a\|b} JOB --yes` | 删除明确指定的卡死/遗留训练 Job。 |
| `./scripts/restart-clientapps.sh --yes` | 滚动重启 A/B ClientApp；仅在无正常训练 Job 时使用。 |
| `./scripts/rebuild-fedavg-adapter.py` | 对已经核验同轮、同初始权重和样本数的两端本地更新执行 FedAvg 重建。 |

完整脚本参数见 [scripts/README.md](../scripts/README.md)。

每次新实验都会在中心结果 PVC 自动保存完整有效参数、Run ID、状态、恢复历史、
纯训练/评估/端到端耗时和客户端训练 loss 加权均值。使用韧性脚本时，完成后还会自动生成本地
`evaluation-results/<experiment-id>/REPORT.md`。因此中心 PVC 是可恢复的权威记录，
本地报告是更直观的索引；两者不需要二选一。

## 故障处理顺序

1. 先执行 `./scripts/status.sh` 与 `./scripts/logs.sh server --follow`；
2. 查看中心端 `experiment_state.json` 和 `./scripts/list-results.sh`；
3. 有完整 `peft_N` 或 `full_N` 时，优先从该 checkpoint 恢复；
4. 仅当 Run 已停止、确认训练 Job 已卡死时，才删除明确命名的 Job 或重启 ClientApp；
5. 不删除模型缓存 PVC、结果 PVC、checkpoint 或持久日志。

## 模型与数据模板

- `Qwen/*`：Alpaca 的 `instruction + input` 映射为 `user`，`output` 映射为
  `assistant`，使用 Qwen ChatML / `apply_chat_template`。
- `openlm-research/open_llama_3b_v2`：使用 Alpaca completion 格式，仅对
  `### Response:` 后的 token 计算 loss。
- FSDP/DDP 对照需保持模型、数据集、轮数、LoRA 参数和评测配置一致，只改变分布式
  策略。

正式 FSDP/DDP 对照参数与实测结果见 [fsdp_vs_ddp.md](fsdp_vs_ddp.md)。

更多预检与对照规范见 [联邦实验预检与启动规范.md](联邦实验预检与启动规范.md)。
