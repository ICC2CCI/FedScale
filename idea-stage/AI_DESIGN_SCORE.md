## 4. Mock Review 正文

### Summary

该投稿为一个跨机构联邦微调系统，集成了确定性 block 粒度部分上传、Bonawitz 式安全聚合、Hadamard–INT16 量化、error-feedback 状态，以及对象存储执行路径。文档记录的结果显示：有用的 block 体积规则性、一个窄的近 fp16 终点结果、以及有意义的 5 轮延迟改进。**但投稿时，被评测的产物实质上小于完整书面协议**，其核心的系统扩展性与多客户端正确性主张**均未建立**。

### Strengths

- block-uniform 产物记录了精确的 H 轮覆盖，并把每轮选中体积波动从 7.3%–37.4% 降到 18.5%–21.5%（2 client、H=5）。
- 量化产物记录了一个具体的数值失败、定位到过早 FP16 rounding 与衰减的量化残差，并给出 20 轮终点 0.985 vs fp16 0.987。
- 时间效率计划报告：单 blob 上传、延迟 fetch、并行 unmask、异步持久化在保持 5 轮 eval 值的同时把整轮时间降到 110–134s。
- block-mask 与 SecAgg 规范在**规范坐标、域分离、重试语义、survivor 冻结、原子提交**方面异常明确。
- 所提出的贡献**可以在不依赖任何虚构算法或密码学新颖性的前提下，诚实地表述为工程集成**。

### Weaknesses（按严重度）

1. **对通用多客户端主张是致命的**：`q=2^16, Q_max=16383` 的配置**只对两个等权客户端**满足规范自己的保守 overflow 条件。加权 FedAvg 的编码也未完全定义。
2. **把规范与已验证执行混为一谈**：阈值分享、dropout 恢复、survivor 冻结、禁止双重重构、fresh-attempt 恢复**全部停留在规范层**。
3. **权威协议不明**：public-mask 规范与被评测算法使用不同的种子派生与 PRG；SecAgg 规范与 active 执行计划在 ChaCha20 vs SHAKE-256 上同样不一致。
4. **证据太窄**：1 个 0.5B 模型、2 个 IID 客户端、1 个种子、1 个比例、1 次 20 轮数值比较、5 轮优化计时 —— **不足以支撑一般化的收敛或系统主张**。
5. **核心系统主张未被测量**：未显示运行时不再按 `RTT × window_count` 扩展，也未刻画 cohort 增大时的 all-to-all setup。
6. **隐私陈述比实际 transcript 窄**：服务器还观察到 per-client losses、timings、参与信息、`num_examples`、`block_energies` 与 `global_amax`。
7. **独立可复现性有限**：run ID 只是文档级引用；跨语言 mask 向量尚未演示。

### Questions for Authors

1. 投稿的方法是**被评测的 2-client 子集**，还是**完整的 dropout 恢复规范**？审稿人应把哪些性质视为已交付？
2. 当前 `q`、`Q_max` 下是否**有意**只支持两个客户端？若不是，使更大或不等 cohort 无歧义的**精确算术与权重编码契约**是什么？
3. 当规范文档与执行文档不一致时，**哪一个 mask 与密码学 PRG 定义是权威的**？
4. 声称的机密性是**仅限更新向量的数值**，还是**覆盖包含 losses、timings、block energies、scale 统计量的完整服务器 transcript**？
5. 有哪一项**已记录的结果**支持"非 `RTT×N`"的扩展性主张？
6. 除了"坐标稀疏化 + memory、Bonawitz 式 SecAgg、Bonawitz-2019 旋转量化、标准传输优化"的组合之外，**所声称的系统贡献是什么**？

### Confidence

- **As-is：4/5** —— 主要的评分驱动发现是**直接的内部矛盾**或**明示的证据限制**。
- **After-remediation：3/5** —— 该分数取决于假设的执行质量，以及 R5 究竟**移除了 `global_amax` 披露**还是**仅仅记录了对其的接受**。

### What Would Move Toward Accept

完整执行 R1–R11 可把投稿从 **4.0 移到约 6.0**。最高杠杆项：

- **R3**：正确且显式的 cohort / 权重 / 模数算术契约；
- **R6**：完整 SecAgg 状态机的一致性验证通过；
- **R7**：所声称 window / cohort 扩展行为的证据；
- **R1**：单一权威可重放 mask 构造；
- **R8**：多种子与不等分/非 IID 的学习证据；
- **R2、R9–R11**：在被评测的工程与未来协议设计之间划出清晰边界。

### Residual uncertainties

- 在已接受的评审边界下 run ID 无法被独立检查；**若原始结果相反，两个分数都可能移动**。
- R2 允许"实现完整协议"或"标注为未来工作"，而 R6 预设了一次一致性验证。**6.0 分假设的是更强、内部一致的那种解读。**
- R5 允许"消除 `global_amax` 披露"或"显式接受它"。选择**接受披露而非移除**不一定降低工程分，**但会封顶隐私主张**。
- H5 按"新增模型复现当前近 fp16 行为"解读；**若复现失败，分数会停在约 4.0 或更低**。
