## 1. 六个重点项的逐项评估

### 项 1 — public、deterministic、replayable、without-replacement 的 block mask

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **大部分已有文献覆盖，小部分属工程组合** |
| **证据等级** | 覆盖性质 `SUPPORTED`（单机）／可重放与跨实现一致 `SPEC_ONLY`＋跨语言部分 `UNKNOWN` |

**分解**：

| 子性质 | 文献状态 | 说明 |
|---|---|---|
| 公开 + 确定性 | **已有文献覆盖** | FedRolex 的 rolling sub-model extraction、FedNILO 的 freeze-index 调度、FjORD 的 ordered dropout **都是公开确定的**。因此"公开/确定性"单独**不构成任何新颖性** |
| 无放回覆盖（H 轮内每块恰好一次） | **已有文献覆盖（思想）/ 方法差异（形式）** | "均匀训练/覆盖全局模型各部分"正是 FedRolex 的核心主张（NeurIPS 2022）。当前的差异在于用 **permutation position mod H** 给出**显式的无放回 100% 覆盖定义**，而 FedRolex 是 rolling window（覆盖靠调度而非形式化保证） |
| **block 粒度 + 均匀带宽** | **方法差异（工程侧，可测量）** | 文献的粒度是**层/宽度**（FedRolex、HeteroFL、FjORD）；当前方案在**扁平化后的 ≈1MB canonical block** 上选，直接以"每轮上传字节近恒定"为目标。本仓库自有对照佐证其必要性：key 级 7.3%~37.4% → block 级 18.5%~21.5% |
| 跨实现可重放（seed+layout → 同一 `mask_hash`） | **仅规范** | S-BM §13.2 要求 ≥3 组跨语言 test vectors；文档未记录已通过。**且规范（ChaCha20/HKDF）与算法文档（Python `random`）在 PRG 上口径不一致**（见 `CURRENT_METHOD.md` §2.3） |
| 与私有更新解耦（mask 在本轮 update 之前确定） | **SPEC_ONLY** | S-BM §3 不变量；无对照实验 |

**可写的最强措辞**：
> "一个面向 canonical block streaming 的公开、确定、可重放的 block 覆盖调度：以 block 粒度把每轮上传量固定为约 ρ 的比例，并在 H 个成功轮次内保证每个可轮转 block 恰好被选择一次。"

**不可写**：
> ~~"我们提出了均匀覆盖的部分训练/子模型选择方法"~~（FedRolex 覆盖）
> ~~"我们首次提出公开确定的选择"~~（FedRolex / FedNILO / FjORD 均已如此）

### 项 2 — 选块状态与 SecAgg 密码学状态解耦

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **工程组合（且分层本身是合理但非新的设计）** |
| **证据等级** | `SUPPORTED`（概念与 2-client 执行）／dropout 分支 `SPEC_ONLY` |

**分析**：

- 规范把这层解耦写得很清楚（S-SA §2 表 + §11.1）：同一 `successful_round_index` 重试时 **public mask 保持不变**，而 **`attempt_id` 递增、全部密码学材料重生**。这是一个**正确的工程不变量**。
- 但"哪些坐标参与聚合"与"如何隐藏这些坐标的数值"分离，是 SecAgg 类协议的**常规分层**（Bonawitz 2017 亦如此：选择参与者/向量在前，掩码在后）。**没有文献意义上的新颖性。**
- **真正的差异点在耦合处，而不是解耦处**：因为 mask 决定**进入 SecAgg 的坐标集合与顺序**，所以 mask 必须在密码学层之前**冻结且 cohort 内完全一致**，并与 `window_plan_hash` / `secagg_session_id` / `mask_hash` 绑定（S-SA §4.1 / §8 表）。这一"冻结坐标计划"的要求，在 SecAgg 文献中不是常见关注点，在 **submodel FL** 文献中却是**已知的危险交界**（SESA, ISIT 2024）。
- 规范还给出了正确但激进的失败语义：`attempt` 失败**不得复用** mask，而 public mask **必须复用**。两个"mask"同名不同义，规范点名要求论文与日志显式区分（S-SA §2）—— 这是**写作纪律**，不是贡献。

**判定**：`工程组合`。可写的价值在于**把分层写成显式协议不变量并给了失败矩阵**（S-SA §11.2 表），属于设计完备性，不是方法贡献。

### 项 3 — server 只看到聚合结果

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **已有文献覆盖（Bonawitz CCS 2017 及其整个后续谱系）** |
| **证据等级** | `PARTIAL`（仅 2 client、无掉线、honest-but-curious） |

**分析**：

- "Server 仅得聚合、不得任一客户端未掩码更新"是 **Bonawitz 2017 的定义性目标**，SecAgg+/LightSecAgg/Turbo-Aggregate 全部继承。**零新颖性。**
- 当前方案在这条线上的**真实处境是承袭而非贡献**：规范 §7 的两类恢复秘密、t_rec-of-n 分享、survivor 冻结、"禁止双重重构"逐条对应 Bonawitz 的 `sk_i`/`b_i` 双分享与 "either/or, not both"。规范自己声明"不把这些密码学原语本身作为论文创新"。
- **反向的比较劣势必须记下**：当前 baseline 是 **all-to-all pairwise**，而文献已有 **SecAgg+**（k-regular 图，O(N log N)）与 **LightSecAgg**（一次性 aggregate-mask 重构，O(d)/user，支持异步）。规范也承认"后续若为大 cohort 改为稀疏 peer graph，必须重新分析掉线恢复与隐私阈值"。**即当前设计在可扩展性上位于已知设计点的弱侧。**
- **一个当前方案独有、但尚未被论证的优点**：Public Block Mask 是**公开且 cohort 一致的**，因此被更新的坐标集合**不携带单客户端私有信息** —— 这恰好正面回答 SESA 提出的"朴素 submodel + 参数级 SA 会泄露索引"的攻击。**这是一个有潜力的论点，但方案文档从未与 SESA 一类攻击模型对照**，目前属于未论证的主张。

**判定**：机密性目标 `已有文献覆盖`；索引隐私这层**存在论证缺口**，是当前唯一可能做出方法差异的地方。

### 项 4 — dropout recovery / survivor threshold

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **已有文献覆盖（成熟机制）** |
| **证据等级** | `SPEC_ONLY`（无任何实验） |

**分析**：

- Bonawitz CCS 2017 已完整给出：DH pairwise mask + self mask + 对 `sk_i` 与 `b_i` 的 Shamir t-of-n 分享 + 服务器在生存集上重建 `b_i`、在掉线集上重建 pairwise secret + "either/or, not both" 约束。当前规范 §7 与 §7.3.3 是**忠实复述**。
- 文献在可扩展性上已走得更远：SecAgg+（O(N log N)）、LightSecAgg（一次性重构 + 异步）、Turbo-Aggregate（O(N log N) + 容忍 50% dropout）。
- **当前状态**：`CURRENT_METHOD.md` §3.3 已核验 —— 三份执行文档（A-PREC / A-SURV / A-FLOW）**均未记录**阈值分享实现、U\* 冻结、attempt_id fresh-mask 重试语义、或 S-SA §16.2 的 5 项 dropout 故障注入中的任何一项。**全部停留在规范。**
- **必须区分的两条线**：SYNC 层（P-PROD SYNC-1/SYNC-2 的 `min_clients_to_aggregate`、迟到 409、缺席 inactive）是 **FL 调度层**的部分参与，**不是** Shamir/threshold dropout recovery。执行文档未建立等价关系，不能把"部分参与已 done"读成"dropout recovery 已验证"。

**判定**：`已有文献覆盖` 且 `SPEC_ONLY`。**没有任何可主张的差异**，仅有规范文本可展示设计完备性。

### 项 5 — Hadamard + INT16 在低上传比例下保持模型效果

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **方法层面已有文献覆盖；实证层面属证据不足** |
| **证据等级** | `PARTIAL`（单模型 / 2 client / IID / 单跑次 / 20 轮）→ 一般化 `UNKNOWN` |

**分析**：

逐项对照 1912.00131（Bonawitz et al., Asilomar 2019）：

| 维度 | 1912.00131 | 当前方案 | 判定 |
|---|---|---|---|
| R = HD 结构化旋转 | ✔ | ✔ pad-p2 → 符号翻转 → FWHT | 相同 |
| 均匀量化 + mod k | ✔（k=2⁸） | ✔（INT16, q=2¹⁶） | 相同 |
| SecAgg 整数域求和 | ✔ | ✔ | 相同 |
| **scale 选择** | **wrapped-normal autotune，由聚合结果反解 bin size** | **每 client 上报 1 个 `global_amax`，server 取 max × 1.05** | **简化替代，且隐私退化** |
| error feedback | 未强调 | `block_memory`(0.9) + `quant_residual`(1.0) | 来自 EF 文献（1901.09847 / 2106.05203），非新增 |

**两条必须写进评审的负面结论**：

1. **`global_amax` 相对父本是隐私上的退步。** 1912.00131 的 autotuning 从**聚合结果**推断分布、**不需要任何单客户端标量**；当前方案要求每 client 每轮上报自己的旋转域 L∞（A-PREC §3.4.1 泄露项 #1）。相对旧 per-window 路径（269 个标量）确有改善，但**相对 2019 年的父本是一条退步**。方案内已有更强的退路（`update_public_block_scales`，公开聚合 max）却因"精度较差"搁置 —— **这正是应被重估的取舍**。
2. **方向与 SOTA 相反。** ScionFL（SaTML 2024）用 1-bit + Kashin 表示把通信压 17.2× 而几乎不损精度；当前方案是**升位宽（INT16）换精度**。因此它的通信效率竞争力**完全来自选块层**（只传 10–20% 参数），**不能归功于量化层**。论文里两者绝不可混着讲。

**实证本身的价值与边界**：
- `202609180941`：R20 eval = **0.985** vs fp16 基线 `20260914-final-clean` R20 = **0.987**（差 0.002）。文档结论是"剩余差距不宜再主要归因于 INT16 位宽"—— 这是**对齐声明，不是等价证明**。
- 边界（全部来自文档自述）：**单一模型**（Qwen2.5-0.5B）、**2 client**、**IID 50/50**、**单跑次、单种子**、**20 轮**、`coverage_h=10`（≈10% 上传）。P-TIME §3 自己写明"通用流程 ≠ 数值从 0.5B 自动成立"。
- 对照点：旧 per-window 路径 `202609162025` R20 = 1.328（无 Hadamard）；修复前 R5 = 2.362（无跑次号）。

**判定**：方法 `已有文献覆盖`；**实证 `证据不足` 于一般化，但足以支撑"该组合在 0.5B 上可行"这一有限陈述。**

| 维度 | 判定 |
|---|---|
| **文献覆盖度** | **纯工程组合（系统实现）** |
| **证据等级** | `PARTIAL`（5 轮数值一致 + 墙钟改善）；扩展性 `UNKNOWN` |

| 优化 | 性质 | 证据 |

| 单 blob（SAW1）+ 通知不拉对象 | 传输层实现 | `202609181151`：`upload_blocks_MiB` 不变（R1=139.4），upload ≈9s vs fp16 ≈16s |

**判定**：`工程组合`。可写为系统实现，**不可写为算法贡献**。

## 2. 任务要求正面回答的五个问题

### Q1. Public Block Mask 相比 FedRolex / federated dropout 真正新增了什么？

**答：真正新增的只有三件，且都不在"部分训练"的原理层。**

1. **block 粒度的均匀带宽预算**：以扁平化 canonical block（≈1MB）为单位选择，使每轮上传字节近恒定（实测 18.5%~21.5%）。文献的粒度是层/宽度，会产生逐轮字节波动。
2. **训练范围与传输范围显式解耦**：客户端训练**完整**模型、只导出被选 block。这与 FedRolex 的"只训部分层"是**相反的取舍** —— 本仓库自有对照显示全训只传部分（S3R11，1.1190）优于 FedRolex 式部分训练（1.1829），代价是算力。
3. **显式可重放审计协议**（seed + layout → 独立重算 `mask_hash`）：这是**规范层面的**新增，但**跨实现验证尚未完成**（PRG 口径在规范与算法文档之间还不一致）。

**明确未新增**：公开性、确定性、覆盖思想、省带宽目标 —— 均被 FedRolex / FjORD / HeteroFL / FedNILO 等覆盖。

### Q2. Hadamard + INT16 相比已有 Hadamard-SecAgg 还剩什么贡献？

**答：方法层面几乎不剩；只剩一个实证和一个（说是退步的）权衡。**

- "Hadamard 旋转 + 均匀整数量化 + SecAgg 整数域求和"这一组合 **= Bonawitz et al. 1912.00131 (2019)**，逐项对应。error feedback 部分来自 1901.09847 / 2106.05203。**无方法新增。**
- **剩下的一**：在 0.5B LLM、≈10% 上传率、真实双集群上，该组合 20 轮收敛到 fp16 基线的 0.985 vs 0.987。这是**实证/系统演示**，不是方法。
- **剩下的二（负向）**：`global_amax` 相比父本的 wrapped-normal autotune 是**以隐私换实现简单**。这可作为"显式记录权衡"写入，**不能写成贡献**，且必须正面解释为何不采用 1912.00131 的 autotune。
- **不可写**：~~"我们提出 Hadamard 旋转用于安全聚合"~~。

### Q3. 2-client、无真实 dropout 的现有验证能支撑多强的 SecAgg 安全主张？

**答：只能支撑最弱的一档 —— 一个 honest-but-curious 服务器在 2 方无掉线时看不到单方未掩码更新。不能再多一个字。**

理由：
1. 已验证的正是 Bonawitz 协议中**不需要秘密分享**的平凡情形（D=0，N−D > T 平凡成立）。
2. **Shamir / 阈值 / U\* 冻结 / dropout 故障注入：全部 SPEC_ONLY**，执行文档零记录。
3. **N=2 时 (T, D) 权衡空间近乎为零**（`q_min ≥ 2`）—— 2-client 实验**原理上无法演示**有意义的阈值安全。
4. **不能**把 SYNC 层的"部分参与已 done"读成"dropout recovery 已验证"—— 二者在文档中未建立等价关系。
5. 反向风险：**SESA (ISIT 2024)** 表明 submodel × 参数级 SA 的索引隐私不是免费的。当前公开公共 mask 可能是好答案，但**该论证尚未做出**。

**不可写**：dropout 鲁棒、阈值安全、抗合谋、N>2 可扩展、抗恶意客户端。

### Q4. object storage、HTTP control plane、single blob、parallel unmask 属于算法还是系统工程？

**答：全部是系统工程，没有一项是算法。**

- 它们不改变数值语义（`202609181151` R1–R5 与 `202609180941` 逐轮相同即为证据），只改变请求次数、写盘时序与并发度。
- 其中"单 blob + 通知不拉对象"确实解决了真实瓶颈（PERF-1 的 handler O(1) 化），属**有价值的系统实现**。
- **但作为系统贡献还需要一个前提实验**：N（window 数）增大时墙钟不随 RTT×N 线性增长。**该压测在文档中是 UNKNOWN。** 在补上之前，"系统贡献"只能写成"在 0.5B 规模上验证"的**有限系统实现**。

### Q5. 当前最合理的研究定位是算法贡献、系统贡献、工程集成，还是有限证据下的组合？

**答：`有限证据下的工程集成` —— 偏向系统，但目前**尚未**达到可发表的系统贡献门槛。**

理由是三层判断：

1. **算法层：被判负。** 四个层分别对应 FedRolex（选块）、Bonawitz 2017（安全聚合）、Bonawitz 2019 + EF（数值路径）、常规分布式系统工程（传输）。**没有一层提供新的算法原理。**
2. **系统层：有素材，缺关键实验。** 素材是"公开可重放 block 覆盖调度 + 与 SecAgg 坐标冻结的耦合 + 单 blob/并行 unmask 的大模型 streaming 集成"；缺的是（a）N 增大时的扩展性证据，（b）跨实现 replayability 的 test vector 落地。规范自己给这个定位的措辞是**"面向大模型 streaming 的系统集成机制，而不是新的密码学协议"**（S-SA §13.3）—— 这是一个**诚实的自我定位**，直接可用。
3. **工程集成层：当前全部证据都在这一层。** 20 轮 0.5B、2 client、10% 上传、真实双集群、与 fp16 基线对齐 0.002。这是**扎实但窄**的集成实证。

**因此最准确的一句话定位**：
> 一个**在真实双集群上完成端到端验证的工程集成**：把已有的公开轮转式部分上传机制与已有的 SecAgg + Hadamard-INT16 数值路径组合起来，在 0.5B LLM、约 10% 上传率下取得与无 SecAgg 基线相当的收敛，并给出可在对象存储 + HTTP 控制面上运行的 streaming 实现。

## 6. Post-review Errata（2026-09-18，评审后追加）

> 由外部评审（`gpt-5.6-sol` @ `xhigh`，threadId `01a0b3e2-54e9-7b03-9024-821824c2a7e4`）裁定触发。

**E-A — "全训优于 FedRolex" 的用法超出授权证据集（`UNKNOWN`）**
- **位置**：本文 §1 项 1（"训练范围与传输范围解耦"行）与 §5 加分点 2。
- **判定**：`2026-09-04-fedrolex-partial-training.md` 属「对照、不进主路径」。**在本轮证据边界内，不得把它当作受支持的比较结果。**
- **保守化表述**：该方案确实"训全模型、传部分 block"（`SUPPORTED`——由书面方案直接定义）；但**相对于 FedRolex 的实证优越性为 `UNKNOWN`**。

**E-B — §1 项 1 的文献家族不完整（`SUPPORTED`）**
- 本文把第 1 层主要对照到 partial-training 家族（FedRolex / FjORD / HeteroFL）。**漏了"带 memory 的通信稀疏化"这一同样自然、甚至更贴切的家族**（客户端全训、只传选中坐标、未传坐标留在 `block_memory`）。
- 应补入 **Stich, Cordonnier, Jaggi, *Sparsified SGD with Memory*, arXiv:1809.07599 (2018)**，并指出 `block_memory` 的 **decay=0.9 属非标准启发式**残差处理。
- **后果**：第 1 层的新颖性被**进一步压缩** —— 剩余区别只是"确定性、cohort 一致、无放回轮转、有界每轮体积的 block 调度"。

**E-C — ScionFL 表述过强（`PARTIAL`）**
- 本文 §1 项 5 写"当前 INT16 Hadamard 在精度/比特轴上弱于它"。该说法**只在 ScionFL 自己的评测设置下成立**；两者在**表示、MPC 机制、任务、威胁模型、总坐标传输量**上均不同。应改为 **"竞争基线"**，不作全局强弱判断。

**E-D — 新增硬约束：SecAgg 算术包络只支持 N=2（`SUPPORTED`）**
- 规范 §9.2 要求 `N_max · Q_max < q/2`；当前实现 `q=2^16, Q_max=16383`：
  - **N=2 → 32766 < 32768 ✅（余量仅 2）**
  - **N=3 → 49149 > 32768 ❌**
- 规范附录 A **推荐 modulus 2^32**，实现却选 2^16。
- **后果**：任何 **N>2 的 cross-silo 可扩展性主张**被硬性阻断，直至改算术契约。详见 `AI_DESIGN_REVIEW.md` §2 D3。

**E-E — 定位结论未变**
- 评审**确认**本文 §2 Q5 的定位判断：**`有限证据下的工程集成`**，且进一步精确化为——**贡献类型 = 「engineering integration」，证据条件 = 「limited-evidence」**。
- 评审同时指出：本文自评的三项弱点中，`global_amax` 方向正确但**强度被夸大**（无任何 DP/互信息/重构分析支撑"低–中"评级），SESA **是缺失的对照/证明义务而非对本设计的现实攻击**（在"公开 cohort 一致 mask + 统一 survivor 集"假设下该索引信道似已被结构性消除，但缺形式化论证），PRG 分歧判断**正确**。
